# RAG Tender — сценарий демонстрации (10–15 минут)

## Позиционирование за 30 секунд

RAG Tender — исследовательская система поиска аналогов промышленной трубопроводной арматуры в номенклатуре LD по строкам тендеров, в том числе по обозначениям MARSHAL, ALSO и TEMPER. В отличие от обычного vector search, конвейер стремится сохранять технические ограничения: DN/PN, тип присоединения, среду, материал, исполнение, привод и тип прохода. Система формирует shortlist для **инженерной проверки**, не утверждает автоматическую эквивалентность.

**Статус:** Technical Preview, не квалифицирован для автономной закупки или монтажа. Показанная архитектура и API имеются в этой ветке; продвинутый веб-кабинет, CSV-first fallback и ручной выбор top-10 — отдельные, неинтегрированные направления.

## Подготовка живой демонстрации

- Используйте отдельную демонстрационную среду, **собственные** API-ключи и **разрешённый для использования** LD CSV + Qdrant snapshot. Один репозиторий без исходных данных не запускает поиск.
- Запускайте обычным `docker compose up -d --build` после заполнения `.env` и `git lfs pull`. Порт по умолчанию **8002**, поскольку Compose автоматически применяет `docker-compose.override.yml`. См. [инструкцию](GETTING_STARTED_RU.md).
- Не открывайте интернету API или PostgreSQL. Демонстрируйте локально/через одобренный TLS proxy; токены храните в переменной окружения и не показывайте экран `.env`.
- До встречи вручную выполните `uv run python -m pytest -q tests` и `uv run python scripts/smoke_production_e2e.py --base-url http://127.0.0.1:8002`. Реальный smoke платный, должен завершиться `PASS`, но заранее **не гарантирован**.
- Откройте `http://127.0.0.1:8002/docs`, нажмите **Authorize** и укажите Bearer-токен. API работает через Swagger UI, специализированный бизнес-интерфейс здесь не поставляется.

## Сценарий запросов в Swagger

**Шаг 1 — исходные обозначения конкурентов.** `POST /v1/match`, тело:

```json
{"products":["Кран шаровой MARSHAL 11с67п 2ЦП.01.0.025.100","Кран шаровой TEMPER 29420125","Кран шаровой стальной фланцевый DN50 PN16 для воды"]}
```

Ожидаемая *форма* ответа: каждый вход получает собственный результат `MATCHED`, `NOT_FOUND` или `ERROR`; для `MATCHED` возвращаются название и артикул LD. **Не обещайте конкретных совпадений** до прогона на актуальном индексе. Покажите, что точное обозначение конкурента проходит через catalog registry, а не превращается сразу в запрос о «похожем кране».

**Шаг 2 — безопасность газа.** `POST /v1/shortlist`, тело:

```json
{"queries":[{"query":"Кран шаровой газовый фланцевый DN50 PN16","working_medium":"GAS"}],"max_candidates":10}
```

В ответе решение только `REVIEW_REQUIRED`. Если кандидаты найдены, несовместимые по среде должны быть вынесены в `blocked_candidates`; неизвестная сертификация не даёт разрешения на газовую эксплуатацию. Если пул пуст — это тоже честный результат, а не повод показать вымышленный подбор.

**Шаг 3 — обработка ошибок и аудит.** Отправьте второй `POST /v1/match` и обратите внимание на `request_id`, `latency_ms` и статус каждой позиции. История хранит JSON слепок запроса и ответа в PostgreSQL. Проверка двух разных слепков с одинаковым `X-Request-ID` есть в `scripts/smoke_production_e2e.py --verify-history`, но требует отдельного SQL read DSN.

## Преимущества, которые можно обсуждать предметно

- **Catalog-first:** характеристики извлекаются из схем производителя / официального источника; provenance и UNKNOWN сохраняются, family-level не выдаётся за точный SKU.
- **Dense + BM25 + RRF:** семантические формулировки и точные технические обозначения дополняют друг друга.
- **Compatibility gates:** явные конфликты DN/PN/среды/присоединения нельзя перекрыть высоким score LLM.
- **Audit + observability:** снимки в PostgreSQL, correlation ID, метрики и структурированные логи.
- **Воспроизводимые эксперименты:** результаты benchmark в [QUALITY_RU.md](QUALITY_RU.md); post-hoc пересчёт GOLD нельзя выдавать за улучшение модели.

## Вопросы, на которые отвечать без преувеличений

| Вопрос | Корректный ответ |
|---|---|
| Это уже готово для закупки? | Нет, Engineer-in-the-loop; критичные параметры, документы и допуски требуют человека. |
| Почему каталог конкурентов? | Для восстановления технического профиля точной модели до поиска в LD, чтобы не терять ограничения при семантическом поиске. |
| Это 100% точность? | Нет; опубликованы только DEV hit-any метрики со строгими оговорками, нет приемочного holdout на итоговом коде. |
| Можно запустить одной командой? | Контейнеры — да после конфигурации, но нужны лицензионный LD CSV, бинарный snapshot из LFS, API-ключи и миграции. |
| Есть UI с top-10 и CSV-first? | Разработки есть в отдельных PR; текущий релизный runtime — HTTP API / Swagger, не объединённый веб-кабинет. |
